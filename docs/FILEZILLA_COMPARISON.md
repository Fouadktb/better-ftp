# FileZilla gap audit

Audit date: 2026-11-16. The baseline comes from inspection of the installed FileZilla application's Site Manager and global settings by the primary agent, supplemented by the official documentation linked below. This is a workflow comparison, not a claim of complete feature parity. No saved server addresses, usernames, or other private connection details are recorded here.

**Existing** means native implementation exists, with final milestone verification still owned by the primary agent. **Current milestone** means being implemented or integrated, not yet a verified release capability. **Backlog** means outside the current milestone. FileZilla Pro documentation is used only where it describes the shared FileZilla client behavior; Pro-only cloud protocols are outside this audit.

| Inspected FileZilla area / workflow                      | Better FTP position                                                     | Status / acceptance gap                                                                                                                                                                                                                                     |
| -------------------------------------------------------- | ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

## Milestone boundary

The current work closes the protocol/authentication, initial-directory, and timeout gaps while preparing the application icon and versioned installer/release pipeline. These items remain **pending final verification**. Installer preparation produces artifacts or a draft prerelease; it does not establish signing, notarization, publication, or cross-platform readiness. See [release gates](RELEASING.md).

Next priorities are safe recursive operations and conflict policies, then bounded parallel transfer workers with independent browsing, followed by reconnect/recovery and bandwidth controls. Trees, synchronization/comparison, and remote editing remain explicit later work. The interface should expose implemented capabilities directly rather than copy settings that have no backend behavior.
